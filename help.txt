# SBUIADMIN - Installation

### Prérequis
- PHP 8.4+ (mysqli, sodium, openssl, curl, gd, mbstring, zip)
- MySQL 5.7+ / MariaDB 10.3+, Apache + mod_rewrite + mod_headers

### Installation
- Depuis GitHub : déposer seul sbuiadmin_netinstall.php dans le dossier
  vide du site et l'ouvrir. L'archive est vérifiée (signature) avant
  extraction, puis l'assistant backdoor/ prend le relais.
- Manuelle : décompresser sbuiadmin-X.Y.zip (releases GitHub), ouvrir backdoor/.
- Clé d'installation : backdoor/install/installer/install-key.php

### Renommer le dossier d'administration
- Installation neuve : nom du dossier d'admin tiré au hasard (étape 4), renommé à la fin.
- Plus tard : renommer le dossier, puis mettre le même nom dans SBADMIN (sbconfig.php).
  Les mises à jour le conservent.

### Proxy ou CDN (Cloudflare) devant le site
- Utilisateurs > IP bloquées > Paramètres : Aucun (défaut, REMOTE_ADDR seule),
  Cloudflare (plages intégrées) ou Autre proxy (adresses/CIDR de confiance).
- Sans proxy déclaré, X-Forwarded-For / CF-Connecting-IP sont ignorés.

### Sentinelle (module de sécurité)
- Journal des refus (connexion, ALTCHA, 2FA, CSRF, droits, IP bloquée,
  anti-flood), mode observation ou protection, IP de confiance.
- Filtres (injection SQL, XSS, ../, inclusion, caractère nul, variables
  globales, scanners, outils d'attaque, fichiers dangereux) : chacun inactif,
  noté seulement, ou selon le mode (403 en protection). Exemptés : IP de
  confiance, administrateurs connectés, mots de passe/jetons, paramètres exclus.
- IP bannies (adresse ou plage, durée ou permanent) : 403 dans les deux modes ;
  bannir depuis le journal. Export CSV du journal. Widgets « Attaques » et
  « IP les plus actives ». Alertes par e-mail (au plus une par 15 min) et
  résumé quotidien, par le SMTP de Contact > Paramètres.
- Conseiller (Sentinelle > Conseiller) : PHP, HTTPS et en-têtes, fichiers exposés,
  comptes, réglages ; score sur 100 (tuile « Score de sécurité » du dashboard).
- Rafales (requêtes/min par IP, compteurs dans datas/cache/sentinelle/) et
  bannissement automatique après N événements graves en M minutes (récidive :
  x30) : seulement en protection ; robots des moteurs vérifiés par DNS.
- Balayage lent : trop de 404 par IP et par heure = événement « scanner ».
- Pays de l'IP au journal : en-tête CF-IPCountry (Cloudflare), sinon clé ipstack
  facultative (Réglages), en cache 30 jours.
- Intégrité (Sentinelle > Intégrité) : fichiers comparés à la liste signée de
  la version installée (cache datas/cache/sentinelle/, signature revérifiée) ;
  modifiés, PHP ajoutés, scripts dans upload/ ; analyse quotidienne en option.
- Bloqué par erreur : créer le fichier vide backdoor/inc/admin/sentinelle-disabled.
- Module tiers : sbSecurityEvent('type', 'info|warning|critical', 'détail',
  'logged|blocked|banned', 'identifiant') note un événement (sans effet si
  Sentinelle est absente).

### Site dans un sous-dossier (ex. /new/)
- Configuration > Générale > URL du site : https://exemple.fr/new/
- .htaccess : ErrorDocument 404 /new/index.php?p=pages&id=404

### Double authentification
- Configurer d'abord le SMTP (Contact > Paramètres), puis l'activer dans
  Configuration > Générale avec le code de test reçu.
- Secours : créer le fichier vide backdoor/inc/admin/2fa-disabled

### Plusieurs sites sur un même hébergement
Chaque site a son sbdbconfig.php (sbdbconfig-<dossier>.php pour les suivants).

### nginx (.htaccess ignorés)
  location ~ ^/ADMIN/inc/plugins/sitemap/sitemap_generator\.php$ { include fastcgi_params; ... }
  location ~ ^/ADMIN/inc/.*\.(php|phar|txt|log|sql|ini)$ { deny all; }
  location ~ /\. { deny all; }
  location ~ (^|/)(sbdbconfig[^/]*|sbsettings-backup-[^/]*)\.php$ { deny all; }
(ADMIN = dossier d'administration, backdoor par défaut)

### Mises à jour (Configuration > Mise à jour)
- Versions signées uniquement, sauvegarde chiffrée avant, retour arrière
  de la dernière mise à jour.
- Sauvegardes : SBUIADMIN_BACKUP_DIR ou 'backup_dir' (sbdbconfig.php),
  sinon à côté de sbdbconfig.php, sinon backdoor/datas/updates/.
  Perdre sbdbconfig.php rend les sauvegardes illisibles.
- Modules (carte « Modules ») : mis à jour séparément du core ; Installer
  (téléchargé si absent), Mettre à jour, Désinstaller (« Supprimer le module »
  retire aussi données, tables et fichiers).
- sbconfig.php (propre au site) n'est jamais remplacé : le core définit ce
  qui manque à un ancien fichier, mais tout define() doit y être précédé de
  defined('X') or (sinon « already defined », erreur en PHP 9).
  Après modification, vider l'opcache si rien ne change.
- vendor/.htaccess refuse tout au web : un dossier de vendor/ propre au site
  qui sert des fichiers (retour de paiement, scripts) doit avoir son propre
  .htaccess (Require all granted). La page Mise à jour les signale.

### Migrations de la base (développeurs)
- backdoor/inc/migrations/<version>.php, modèle dans inc/sbuiadmin-update-db.php
- Idempotentes (méthodes SbMigration), avec une partie 'down' si possible.
- Supprimer en deux versions : N n'utilise plus, N+1 supprime.
- Module : datas/modules/<nom>/module.php (version, core minimal),
  install.php (tables), migrations/<version>.php.
- Admin du module : admin/<nom>.php (contrôleur) et admin/tpls/ (gabarits),
  prioritaires sur backdoor/datas/modules/<nom>.php et tpls/ ; mêmes
  contrôles (droits, CSRF). Les gabarits du core passent toujours avant.
- Widgets du dashboard : widgets/<clé>.php (clé de 17 caractères au plus)
  retourne array('title', 'icon', 'link', 'format' => 'kpi'|'card',
  'params' => array('nb' => array('label', 'type' => text|number|select|yesno,
  'default', 'min', 'max', 'options')), 'render' => function ($params) {...}).
  kpi : render() retourne la valeur ; card : du HTML (à échapper), ou des
  variables pour widgets/<clé>.tpl. Masqué sans le droit « voir » du module.
  Tuile enrichie : array('value', 'compare', 'trend' => % signé,
  'trend_good' => 'down' si une baisse est bonne). 'width' => 4|6|8|12
  (carte, modifiable à l'ajout), 'scripts' => array(...) chargés une fois.
- Module propre à un site : 'origin' => 'site' dans module.php (jamais
  installé ni mis à jour depuis GitHub, fichiers hors mise à jour du core).
- 'csrf_get' => array('duplicate', ...) : actions GET sensibles du module
  (jeton exigé, ajouté aux liens par csrf.js). Tout POST de l'admin exige
  le jeton (ajouté automatiquement aux formulaires, fetch et jQuery).
- 'modifiers' => array('maFonction', ...) : fonctions utilisables dans les
  gabarits Smarty (peuvent être définies dans inc/functions.php).
